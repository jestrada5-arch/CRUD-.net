3. Detalle de lo encontrado antes

Format String Error (medio, 7 instancias)

ZAP envió cadenas con marcadores de formato (%n%s%n%s… y %1!s%2!s…) en los campos del cuerpo y marcó una posible vulnerabilidad cuando el servidor cerró la conexión. En .NET este tipo de ataque no aplica de forma directa, y el informe no traía evidencia; lo más probable es que fueran errores 500 por datos que no cabían en las columnas de MySQL.

  • POST /api/Clientes: campo cui
  • PUT /api/Clientes/10: campos apellidos, cui, direccion, nit, nombres y telefono

Falta X-Content-Type-Options (bajo, 4 instancias)

  • GET /api/Clientes
  • GET /api/Clientes/10
  • GET /openapi/v1.json
  • POST /api/Clientes

Strict-Transport-Security no establecido (bajo, sistémica)

  • GET /api/Clientes, GET /openapi/v1.json, POST /api/Clientes
  • GET /robots.txt y GET /sitemap.xml

Reexaminar Cache-Control (informativo, 3 instancias)

  • GET /api/Clientes, GET /api/Clientes/10, GET /openapi/v1.json

5. Observaciones y límites

Pendiente de revisar: el escaneo "después" registró un 22 % de fallos de red y un error en zap.log. Antes de dar el resultado por definitivo conviene comprobar que la API siguió activa durante todo el escaneo y que el escaneo activo llegó al 100 %. Si no fue así, hay que repetirlo.
  • Format String solo se detecta con el escaneo activo. Su ausencia en el segundo informe es una buena señal, pero depende de que ese escaneo se haya completado.
  • ZAP prueba solo lo que descubre desde afuera (los endpoints del OpenAPI). No revisa el código fuente, los secretos ni la lógica de negocio.
  • El informe "antes" original en HTML se sobrescribió al generar los informes siguientes (ZAP nombra los archivos solo con la fecha). Los datos de este documento sobre el "antes" se reconstruyeron a partir del contenido de ese primer informe.

6. Correcciones aplicadas

ArchivoCambio
Models/ClienteInputDto.cs (nuevo)Datos de entrada de POST y PUT con longitudes máximas según las columnas de la base de datos y expresiones regulares que rechazan caracteres no permitidos. Los datos inválidos devuelven 400.
Controllers/ClientesController.csPOST y PUT reciben el DTO en lugar de la entidad. El id sale de la URL.
Program.csMiddleware de cabeceras de seguridad, AddProblemDetails y UseExceptionHandler para errores 500 genéricos, y UseHsts.
appsettings.Development.jsonBandera temporal EnableHstsForScan para que HSTS se envíe en localhost durante el escaneo (debe volver a false después).

7. Recomendaciones pendientes

  • Autenticación y autorización: la API sigue abierta; cualquiera puede leer, modificar y borrar clientes. ZAP no lo marca como alerta, pero es el mayor riesgo restante.
  • Secretos: sacar las contraseñas de appsettings.json (user secrets o variables de entorno) y cambiarlas si estuvieron en un repositorio público.
  • HSTS en producción: mantenerlo activo con un max-age largo y un dominio real con HTTPS.
  • Repetir el escaneo activo con la API estable y revisar el zap.log si persisten fallos de red.
  • Paquetes: revisar vulnerabilidades con dotnet list package --vulnerable --include-transitive.
